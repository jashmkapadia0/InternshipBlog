<section class="page-hero"><p class="eyebrow">02 / METHOD</p><h1>Make the comparison reproducible.</h1><p class="lede">A planned workflow from measurement model to evaluation, with decisions recorded as the project develops.</p></section>
<section class="section prose-section"><figure class="article-figure"><img src="{{ '/assets/images/workflow.svg' | relative_url }}" alt="Planned workflow from sky model, UV sampling, visibilities, and dirty image to CLEAN or U-Net reconstruction and metrics"><figcaption><span>FIG. 04</span> Project workflow schematic. This is a plan, not a record that stages have been completed.</figcaption></figure>
<h2>Workflow</h2><ol class="numbered-steps"><li><strong>Define inputs and provenance.</strong> Record dataset or simulation source, units, field, observation or simulation settings, and permitted use.</li><li><strong>Specify the forward problem.</strong> Document sky reference, array/UV sampling, visibility generation or calibration, noise model, weighting, and image grid.</li><li><strong>Form the dirty image.</strong> Apply a documented imaging transform to the sampled visibilities and retain the associated PSF and normalization.</li><li><strong>Run Högbom CLEAN.</strong> Record implementation, loop gain, stopping rule, clean mask if any, restoring beam, and compute environment.</li><li><strong>Train and apply a U-Net.</strong> Define input and target representations, train/validation/test split, architecture, loss, optimizer, augmentations, checkpoint selection, and inference settings.</li><li><strong>Evaluate on held-out cases.</strong> Compare both reconstructions with the same reference and report metric definitions, units, aggregation, and runtime conditions.</li></ol>
<h2>Fair-comparison principles</h2><ul><li>Keep test examples separate from training and model selection; document how the split avoids leakage.</li><li>Use the same cases, reference image, field of view, pixel grid, flux scale, and evaluation mask wherever possible.</li><li>Report preprocessing and postprocessing that affect flux or resolution.</li><li>Show representative images and residuals alongside aggregate metrics; do not use metrics alone.</li><li>State software versions, hardware, timing boundaries, and whether setup or data transfer is included in runtime.</li><li>Record limitations and failed or inconclusive experiments as well as positive results.</li></ul>
